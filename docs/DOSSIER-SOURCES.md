## First real canary candidate: `clinicaltrials-gov-api-v2` (inspect + access PoC + local adapter, 2026-10-03; NOT activated)

Slot C2 (GLOBAL_MEDICAL_FRONTIER). Scope of this record: what was inspected, what one bounded official request proved, and what the local adapter + one real local end-to-end run showed. Nothing is activated, scheduled, deployed or written to production; D1 0031 is not applied remotely.

**Inspect (read-only, `source-lifecycle inspect` + catalog + code):** source exists (`research-sources.json`, role `TRIAL_REGISTRY`, discovery function `EVIDENCE_ENRICHMENT`, `CANONICAL_ACTIVE`, verified 2026-09-05; feed `research-clinicaltrials-gov-api-v2`, `RESEARCH_REGISTRY`, 1440 min); lifecycle state ACTIVE, TIME_SENSITIVE ON, EVERGREEN DISABLED. The existing acquisition (`ingestClinicalTrials` in `research-apis.ts`) runs a fixed narrow legacy query (`stethoscope OR auscultation OR "artificial intelligence" medicine`, `pageSize` 15), no pagination, no cursor, and stores only NCT id, title and first-post/start date as Hub `source_items`; it keeps no conditions, interventions, phase, status or sponsor. Legal note on file: official public REST API v2, enrichment only. Terms-of-use and rate-limit review is still an owner/access item (the response carried no rate-limit headers).
**Reuse mode: `ADAPTER_REQUIRED`.** The existing items cannot support dossier observations (no topic metadata; the slice is a biased legacy query), and changing that reader would alter its Time-Sensitive semantics. The smallest extension is a separate local dossier reader of the SAME official source id (`apps/worker/src/dossier/clinicaltrials.ts`) that reads a different, bounded slice into dossier-owned thin references; the legacy acquisition is untouched, no second source record was created, and registering this reader as a dossier sensor remains `SOURCE_LIFECYCLE_REQUIRED`.

**Access PoC: PASS** (one official request, no secret, 5 records, field projection): HTTP 200; `totalCount` and `nextPageToken` pagination; stable `NCT########` ids; `StudyFirstPostDate` / `LastUpdatePostDate`; conditions, intervention names and types, phase, status, lead sponsor, study type. No literature or effectiveness interpretation is needed to normalize it.

**Dossier semantics:** trial existence/activity is a DISCOVERY signal (`GLOBAL_RESEARCH_ACTIVITY`, kind `RESEARCH_ACTIVITY_COUNT`, provenance `ADMINISTRATIVE`, value `NOT_APPLICABLE`, subfamily `CONDITION` or `INTERVENTION`, observed at the first-post date). It never represents effectiveness, trial success, evidence quality, a recommendation or medical truth; the projection excludes results, outcomes, descriptions and publications. Intervention TYPE (the API's own enum) maps to a dossier domain + concept CLASS only (supplement → SUPPLEMENT, others → HEALTH); names come only from the metadata.

**Boundedness:** one request per run, `pageSize` = the per-run cap, fixed `fields`, newest first, optional lower date bound, the API token only reported as the checkpoint. Production caps (per-run fetch/item cap, backfill, how far back, cadence) remain `OWNER_DECISION_REQUIRED`; the numbers used in the local runs are PoC parameters, not defaults.

**Real local end-to-end (in-memory database only; `scripts/dossier-clinicaltrials-poc.mjs --live`):**
- Run 1 (25 newest records): chain completed (25 refs, 98 observations, 98 PROPOSED concepts, 98 WATCH candidates, immutable snapshots) but no topic appeared in two independent records, so nothing met the local PoC criterion (a topic in ≥2 independent records is review-ready FRONTIER). Not counted as review-ready.
- Run 2 (100 newest records, still one request, same criterion): 100 refs, 414 observations, 396 PROPOSED concepts (every label present in the response; none ACTIVE), 396 stable EVERGREEN candidates, 9 review-ready FRONTIER (e.g. a condition registered in two independent trials), explainable snapshots with provenance to `https://clinicaltrials.gov/study/NCT…`. The same real page replayed with only the caps configured stays `WATCH / NOT_READY` for every candidate (fail closed). No review, no Hub item, no runtime-state row was written.

**Findings for the owner:** (1) the newest-first slice of 100 is one first-post day, so persistence across days cannot be observed from one page; (2) generic registry terms ("placebo", "healthy subjects", very common conditions) become concept proposals like any other; filtering them is a policy choice, not a hard-coded list; (3) one candidate is created per proposed concept (396 from 100 trials), so a candidate-creation eligibility rule is needed before any scheduled reader (`OWNER_DECISION_REQUIRED`, P4); (4) terms/rate-limit confirmation and the lifecycle registration are still open.

### Canary stabilization: editorial eligibility (2026-10-03; local only, NOT activated)

**Distinction implemented:** observation != concept != candidate-eligible topic != dossier candidate (`eligibility.ts`, contract section `editorial_eligibility`, migration 0031 columns `source_role` / `candidate_signal_eligible` / `eligibility_reason`, still local-only and unapplied). The gate sits in three places: the pipeline only aggregates ELIGIBLE concepts for candidates, candidate aggregates read only eligible observations, and `evaluateTarget` refuses a non-eligible concept (`NOT_ELIGIBLE`), so no caller can bypass it.

**ClinicalTrials.gov field semantics (`CLINICALTRIALS_FIELD_ROLES`, roles not entity lists):** conditions and interventions are TOPIC_BEARING; phase, overall status and study type are CONTEXT_ATTRIBUTE; lead sponsor is SOURCE_ACTOR; the healthy-volunteer flag is a POPULATION_DESCRIPTOR co-signal; record id and first-post date are OPERATIONAL_METADATA. Only topic-bearing fields create concept observations; the rest stay in the bounded evidence span. Refinements use the record's own structure, never wording: an intervention is COMPARATOR_OR_CONTROL only when every arm carrying it is a PLACEBO_COMPARATOR, SHAM_COMPARATOR or NO_INTERVENTION arm (the API's closed ArmGroupType enum); an ACTIVE_COMPARATOR arm is an active intervention and stays topic-bearing (a real record compares two probiotics head to head, both ACTIVE_COMPARATOR); a condition stays potentially topic-bearing: the healthy-volunteer flag is population / eligibility CONTEXT only and is not a negative signal (superseded the earlier REVIEW_REQUIRED rule, see the lifecycle section below). The source's own browse match adds TOPIC_COHERENT; its absence is never negative, because the newest records carry empty browse modules.

**Support dimensions kept apart:** several independent records of one signal family are `SOURCE_LOCAL_REPETITION`; only two or more signal families give `MULTI_SIGNAL_FAMILY_SUPPORT`. A trial record supports "this topic has registry activity" and nothing about effect, success or recommendation.

**The `2` threshold:** the live script's "topic in two independent records" rule is a POC_ONLY test criterion (`POC_ONLY_TEST_MIN_ORIGINS` in `scripts/dossier-clinicaltrials-poc.mjs`); a test scans product code for numeric class criteria and word lists and finds none. Candidate classes stay owner policy; unset gives WATCH / NOT_READY.

**Access / terms check (official ClinicalTrials.gov material only; the site is a JavaScript app, so the text was read from its own published page assets and the OpenAPI document at `/api/oas/v2`):** public REST API v2 (`servers: https://clinicaltrials.gov/api/v2`, version 2.0.5 at check time); no security scheme or key in the specification; pagination via `pageToken` / `nextPageToken`, later pages must repeat the first page's parameters, `pageSize` default 10 and coerced down to 1,000; the documentation warns against too large a page with unlimited fields; **no rate limit is published** in the specification, API landing text or terms (none inferred). Terms and Conditions (data available at no charge; no warranty): in any publication or distribution you should attribute ClinicalTrials.gov, keep data current, display the date the data were processed, and state any modification; no proprietary claim; no e-mail extraction for marketing; some data may carry third-party copyright. **Open consequence for owner:** a dossier handoff or any display of registry-derived facts must carry that attribution and processing date; the dossier reader stays `legal_status UNRESOLVED` until the source lifecycle records the review.

**Real canary re-run (SUPERSEDED by the lifecycle correction below; kept as history) (POC_ONLY, one request, 100 newest records, not tuned):** 414 observations (all retained), 396 PROPOSED concepts (none ACTIVE) -> ELIGIBLE 313, REVIEW_REQUIRED 78 (record accepts healthy volunteers, no browse match), WATCH_ONLY 5 (placebo/sham/no-intervention-only controls); 313 candidates (310 WATCH, 3 FRONTIER under the POC_ONLY test criterion; 0 review-ready without owner criteria); every candidate target ELIGIBLE, no candidate for any non-eligible concept; eligibility identical under a caps-only policy. Success is the semantic separation, not a count. Honest limits: candidate volume fell only from 396 to 313 because this source's structure separates controls and ambiguous population entries but cannot say a condition is too common or too generic, so a candidate-creation policy for the remaining WATCH volume is still `OWNER_DECISION_REQUIRED` (P4); the healthy-volunteer rule also parks real diseases (a recall cost, kept reviewable).

### Lifecycle correction: WATCH is not a candidate (2026-10-03; local only, NOT activated)

**Inspection before the change:** every eligible concept with an aggregate created a durable row in `dossier_candidates` (313 of 396 in the previous canary), WATCH was stored as a candidate class AND state, and an immutable snapshot was written for every one of them. No pre-candidate representation existed, but eligibility (grouped observation summary) and the live signal aggregates were enough to derive one, so no table was added.

**Canonical lifecycle (owner decision):** DISCOVERED -> WATCH -> CANDIDATE -> REVIEW -> ACCEPT / REJECT / SNOOZE, and WATCH != DOSSIER_CANDIDATE. Implemented as: observation -> concept -> editorial eligibility -> signal aggregate -> WATCH (derived) -> promotion gate -> durable candidate -> immutable snapshot -> review. A new candidate starts at `CANDIDATE`, becomes `REVIEW` only with a non-WATCH class, and snapshots exist only for promoted candidates. An already-promoted target keeps its stable identity and its snapshots; a human REJECT is unchanged and is not resurfaced.

**Promotion policy (SUPERSEDED by the canonical promotion routes below; kept as history):** `candidate_promotion` enables CONVERGENCE (independent support from more than one signal family) and/or SOURCE_SPECIFIC_FRONTIER (families an owner approved to promote alone). No source has such a policy, so the default for ClinicalTrials-only data is WATCH + NOT_READY_FOR_CANDIDATE. No numeric threshold exists in product code; the old "two independent studies" rule is POC_ONLY in the script, and the TEST_ONLY promote-everything policy lives only in test support (a test fails if either leaks into runtime).

**Healthy volunteers (owner decision):** removed as a negative signal. Conditions stay potentially topic-bearing; a reliable semantic classifier can later be injected for TOPIC_COHERENT / REVIEW_REQUIRED / POPULATION_CONTEXT (the slot exists, no classifier ships, no NLP/LLM was added).

**Attribution:** the generic capability above carries the ClinicalTrials terms (attribute the source, show the processing date, state modifications, keep data current, no proprietary claim, no contact extraction for marketing, third-party rights may apply); the reader report and the handoff carry the notice. Verified access findings are unchanged: public API, no key, pagination as documented, no published rate limit.

**Schema:** no schema change in this phase (migration 0031 remains local-only; the three eligibility columns were added to it earlier); no 0032.

**Real canary after the lifecycle correction (POC_ONLY, one real request, 100 newest records, page size not tuned):** 100 studies, 414 observations (all retained), 396 PROPOSED concepts (none ACTIVE) -> ELIGIBLE 391, REVIEW_REQUIRED 0, WATCH_ONLY 5 (placebo / sham / saline-control-only), NOT_EDITORIAL_TOPIC 0. A separate POC_ONLY promotion policy on the same real page promotes 391 with one snapshot each (path PROMOTED_BY_SOURCE_SPECIFIC_FRONTIER) and 8 review-ready under a POC_ONLY class criterion, proving WATCH -> candidate -> snapshot still works; neither number is a product result. ### Canonical promotion routes and the second signal world (2026-10-03; local only, NOT activated)

**Promotion (owner decision):** the gate is editorial eligibility + a valid promotion route + quality/integrity not rejected, never a scientific-evidence judgment. Routes: (1) MULTI_SIGNAL_FAMILY_CONVERGENCE, the default automatic route (eligible support from more than one independent signal family; "more than one" is the definition, a policy can only make it stricter); (2) SOURCE_SPECIFIC_FRONTIER, supported but default DISABLED (one owner-approved family may promote alone; ClinicalTrials has no such permission, so ClinicalTrials-only stays WATCH); (3) HUMAN_PROMOTION, an explicit, audited editorial promotion of a WATCH target (review event WATCH_TARGET / PROMOTE, effect limited to candidate creation, not ACCEPT, eligibility and integrity still apply). No numeric threshold exists. WATCH is a pre-candidate lifecycle state, not a candidate class: the class enum is STRONG / EMERGING / CORRECTIVE / FRONTIER, and a promoted candidate carries the neutral EMERGING class unless owner class criteria say otherwise. A factual public-health topic without a credible anchor is refused by every route.

**Access PoC (read-only, no secret):** structure queries (dataflow list, data structure, one all-years Turkiye slice for shape) and one bounded slice `TUR.A.CSEM.DT._T._T._Z......?lastNObservations=1` returned HTTP 200, 49 rows (one latest annual value per cause group), names from the source codelist, annual period with start/end, unit, stable URL. OECD web pages (terms, API explainer) answered 403 to this client and were not bypassed: **terms and any rate limit are UNVERIFIED** (no rate limit is assumed); attribution is declared conservatively (source, processing date, modifications, third-party rights) and the reader stays `legal_status UNRESOLVED`. The dataflow itself states the underlying source (WHO Mortality Database).

**Semantics (`oecd.ts`):** TURKEY_HEALTH_BURDEN, kind BURDEN_UTILIZATION, provenance ADMINISTRATIVE, subfamily = the measure (CSEM), value = deaths with its unit, geo = TUR, window = SOURCE_PERIOD (the source annual period) so no FAST window and no momentum is ever used; a missing value is UNKNOWN, never zero; one release slice is one origin, a newer period is a new item. Only the cause-of-death dimension creates concepts; geography, frequency, measure, unit, age, sex and period stay context, SDMX reserved codes (_T total, _Z not applicable, ...) are never topics, and no word list is used. Not interpreted as importance ranking, comparison or causal claim.

**Real local E2E + real convergence (OECD live: one request; ClinicalTrials: replay of the saved real response, no request; DEFAULT policy):** 49 rows -> 48 observations / 48 PROPOSED concepts (the Total placeholder is context), all ELIGIBLE, all SOURCE_PERIOD, all MEASURED with unit Deaths.
