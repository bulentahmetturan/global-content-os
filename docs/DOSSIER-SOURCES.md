## First real canary candidate: `clinicaltrials-gov-api-v2` (inspect + access PoC + local adapter, 2026-10-03; NOT activated)

Slot C2 (GLOBAL_MEDICAL_FRONTIER). Scope of this record: what was inspected, what one bounded official request proved, and what the local adapter + one real local end-to-end run showed. Nothing is activated, scheduled, deployed or written to production; D1 0031 is not applied remotely.

**Inspect (read-only, `source-lifecycle inspect` + catalog + code):** source exists (`research-sources.json`, role `TRIAL_REGISTRY`, discovery function `EVIDENCE_ENRICHMENT`, `CANONICAL_ACTIVE`, verified 2026-09-05; feed `research-clinicaltrials-gov-api-v2`, `RESEARCH_REGISTRY`, 1440 min); lifecycle state ACTIVE, TIME_SENSITIVE ON, EVERGREEN DISABLED. The existing acquisition (`ingestClinicalTrials` in `research-apis.ts`) runs a fixed narrow legacy query (`stethoscope OR auscultation OR "artificial intelligence" medicine`, `pageSize` 15), no pagination, no cursor, and stores only NCT id, title and first-post/start date as Hub `source_items`; it keeps no conditions, interventions, phase, status or sponsor. Legal note on file: official public REST API v2, enrichment only. Terms-of-use and rate-limit review is still an owner/access item (the response carried no rate-limit headers).
**Reuse mode: `ADAPTER_REQUIRED`.** The existing items cannot support dossier observations (no topic metadata; the slice is a biased legacy query), and changing that reader would alter its Time-Sensitive semantics. The smallest extension is a separate local dossier reader of the SAME official source id (`apps/worker/src/dossier/clinicaltrials.ts`) that reads a different, bounded slice into dossier-owned thin references; the legacy acquisition is untouched, no second source record was created, and registering this reader as a dossier sensor remains `SOURCE_LIFECYCLE_REQUIRED`.

**Access PoC: PASS** (one official request, no secret, 5 records, field projection): HTTP 200; `totalCount` and `nextPageToken` pagination; stable `NCT########` ids; `StudyFirstPostDate` / `LastUpdatePostDate`; conditions, intervention names and types, phase, status, lead sponsor, study type. No literature or effectiveness interpretation is needed to normalize it.

**Dossier semantics:** trial existence/activity is a DISCOVERY signal (`GLOBAL_RESEARCH_ACTIVITY`, kind `RESEARCH_ACTIVITY_COUNT`, provenance `ADMINISTRATIVE`, value `NOT_APPLICABLE`, subfamily `CONDITION` or `INTERVENTION`, observed at the first-post date). It never represents effectiveness, trial success, evidence quality, a recommendation or medical truth; the projection excludes results, outcomes, descriptions and publications. Intervention TYPE (the API's own enum) maps to a dossier domain + concept CLASS only (supplement → SUPPLEMENT, others → HEALTH); names come only from the metadata.

**Boundedness:** one request per run, `pageSize` = the per-run cap, fixed `fields`, newest first, optional lower date bound, the API token only reported as the checkpoint. Production caps (per-run fetch/item cap, backfill, how far back, cadence) remain `OWNER_DECISION_REQUIRED`; the numbers used in the local runs are PoC parameters, not defaults.

**Real local end-to-end (in-memory database only; `scripts/dossier-clinicaltrials-poc.mjs --live`):**
- Run 1 (25 newest records): chain completed (25 refs, 98 observations, 98 PROPOSED concepts, 98 WATCH candidates, immutable snapshots) but no topic appeared in two independent records, so nothing met the local PoC criterion (a topic in ≥2 independent records is review-ready FRONTIER). Not counted as review-ready.
- Run 2 (100 newest records, still one request, same criterion): 100 refs, 414 observations, 396 PROPOSED concepts (every label present in the response; none ACTIVE), 396 stable EVERGREEN candidates, 9 review-ready FRONTIER (e.g. a condition registered in two independent trials), explainable snapshots with provenance to `https://clinicaltrials.gov/study/NCT…`. The same real page replayed with only the caps configured stays `WATCH / NOT_READY` for every candidate (fail closed). No review, no Hub item, no runtime-state row was written.

**Findings for the owner:** (1) the newest-first slice of 100 is one first-post day, so persistence across days cannot be observed from one page; (2) generic registry terms ("placebo", "healthy subjects", very common conditions) become concept proposals like any other; filtering them is a policy choice, not a hard-coded list; (3) one candidate is created per proposed concept (396 from 100 trials), so a candidate-creation eligibility rule is needed before any scheduled reader (`OWNER_DECISION_REQUIRED`, P4); (4) terms/rate-limit confirmation and the lifecycle registration are still open.
