# System evidence (P4)

One canonical evidence truth for both repos: `docs/evidence/system-evidence.ndjson` (append-only, one JSON event per line, folded into one record per `evidence_id`). It lives here, not in `channel-content-os`, so the issue register projection and its CI gate stay in one repo; `@ccos/scripts/evidence.mjs` delegates to this CLI.

## What becomes evidence

User-reported issues, runtime findings, tests, CI, production checks, audits, incidents, agent findings, migrations, context telemetry, security findings. Content relevance feedback (editorial accept/reject) is P5 and is refused here with `WRONG_LOOP`.

## Lifecycle

`CAPTURED → CLASSIFIED → ROUTED → ACTION_REQUIRED | NO_ACTION → APPROVED → IMPLEMENTED → VERIFIED → CLOSED`, plus `DEFERRED`, `REJECTED`, `ROLLED_BACK`.

Guards (enforced by `packages/system-evidence/index.mjs`, not by convention):
- `APPROVED` needs a human, operator or review-gate actor.
- `IMPLEMENTED` / `VERIFIED` need an implementation reference; `VERIFIED` needs a verification reference and an after state when a before state exists.
- `CLOSED`, `REJECTED`, `ROLLED_BACK` need a resolution; a machine actor cannot close material evidence.
- `DEFERRED` needs owner, reason and review trigger (optional `review_by`; overdue deferrals show in `audit`).

Evidence never edits a canonical rule, registry or config. Fixes go through the owning subsystem's normal path and are linked back as references.

## Commands

```
node scripts/evidence.mjs report-issue "<summary>" --actor human:<name> --apply   # user problem -> S## ID + owner
node scripts/evidence.mjs capture --type AUDIT --origin agent --summary "..." --actor agent:<id> --apply
node scripts/evidence.mjs route <id> [--owner P3/security] [--invariant ID]
node scripts/evidence.mjs implement <id> --impl commit:<sha> ... verify / close / defer / reject / rollback
node scripts/evidence.mjs show <id> | audit [--check] | audit-input | project [--check]
```

Without `--apply` every mutating verb is a dry run. Every audit starts from `audit-input` (all open and deferred items, including user-reported issues).

## Routing

Owners are routed from the summary (context → P4/context-routing; cadence, scheduler, source → P2/source-runtime; Hub, triage → P2/hub-approved-brief; auth → P3/security; callback, deploy, D1, GitHub, Cloudflare → P3/operations; render, QA → P3/ccos-production); anything else lands in P4/evidence-triage. `--owner` overrides.
