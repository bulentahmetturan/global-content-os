## 0. What preparation found (and fixed locally)
1. **The deployed Worker could not run the Eurostat reader at all.** The production routes were hard-wired to the V1 profile, the V1 registry and the ClinicalTrials / OECD readers. Prepared locally: `POST /run` for the V2 reader id selects `DOSSIER_CANARY_V2`, the V2 registry and the Eurostat reader (guarded to one https host, one dataset path, `geo=TR`); `?profile=v2` selects the V2 read model; new read-only `GET /eurostat-report?run_id=`. A V1 reader id or no parameter behaves exactly as before.
2. **Candidate persistence guard (hard safety rule).** Under V2 the derive phase uses the dry-run promotion gate (`gateTarget`) instead of `evaluateTarget`: a concept that reaches the promotion boundary throws `V2_HARD_STOP_PROMOTION_ELIGIBILITY_REACHED` (records `PROMOTION_ELIGIBILITY_REACHED=YES`) before any candidate or snapshot write. V2 profile fields `candidate_persistence = snapshot_persistence = FORBIDDEN` are validated. Natural data never reaches it (unknown granularity fails closed); a TEST-ONLY fabricated granularity proves the stop.
3. **Resume contract, exposed now:** once the work list is persisted and the phase flips to INGEST a resume never refetches. The ONLY refetch window is a platform kill inside the first (FETCH) invocation between the HTTP response and that flip (at most 8 statements, nothing ingested yet); it ends in the identical durable state (tested) and is bounded by the 3-request logical-run limit. This is not a blocker.
4. **Operator CLI**: `--once` (exactly one invocation, then stop), `--profile v2`, `eurostat-report --run-id`.

## 7. Run id contract
The Worker creates the run id (`crun_<uuid>`) on the first `POST /run` without a `run_id`. The operator executes that first invocation with `--once`, records the id, and passes `--run-id` on every later call (the Worker refuses an unknown or foreign id: `RUN_NOT_FOUND_FOR_READER`; a second logical run is impossible while one is active: `RUN_ALREADY_ACTIVE`, and after a COMPLETED run: `RUN_QUOTA_EXHAUSTED_OPERATOR_REVIEW_REQUIRED`). If an invocation's response is lost, the id is read with `runs --reader dossier-eurostat-tr-causes-of-death --profile v2`. A FAILED run does not consume the quota: therefore **after any FAILED the operator sets the reader control to 0 immediately and does not call `run` again** (a new run would be a second logical run and needs a new owner decision). No automatic restart, no retry that generates a new run.

## 8. Source / checkpoint contract
One Eurostat fetch; the normalized work list is persisted before INGEST and every resume uses it (section 0.3 for the one bounded exception). A platform failure never triggers a ClinicalTrials refetch, a second logical run or a restart from zero.

## 15. Hard stops, 16. Platform-termination policy
Hard stops: the 15 criteria in the hard-limits JSON (new logical run, ClinicalTrials or OECD request, run id mismatch, checkpoint corruption, lease or concurrency failure, D1 > 800, schema or integrity error, duplicate observation, selector inconsistency, automatic alias, candidate / snapshot / review attempt, ACTIVE transition, frontier or policy mutation, security failure, unexpected nonrecoverable 5xx, GCOS not READY, P5 failure). No auto-repair in production. `MAX_RECOVERABLE_PLATFORM_TERMINATIONS = 3`: after one clearly attributable platform termination (tail outcome exceededCpu / exceededResources or a platform error page): stop, capture evidence, confirm via `runs` that the same run is RUNNING with its checkpoint intact, wait for lease expiry (45 s), run `eurostat-report` to confirm invariants (no duplicate, no candidate, no extra run, source requests within bound), then resume the SAME run with `--run-id`. The fourth termination, or any non-platform integrity failure on its first occurrence, is a HARD STOP. The CPU root cause stays `UNRESOLVED_PLATFORM_ENFORCEMENT`; nothing here claims it is solved.
