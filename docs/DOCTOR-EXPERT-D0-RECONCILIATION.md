## 10. item_key storage decision (recommendation)

RECOMMENDATION B — associated item-identity table (not new columns on
`source_items`). Rationale from repository reality, not preference:

1. `source_items.dedupe_key` + `UNIQUE(route,dedupe_key)` is load-bearing
   (migration `0025` rewrote keys on the `hekimler→tip_toplulugu` rename;
   Temporal V2 tests assert byte-identical row semantics across `0028`).
   Overloading platform item identity (`youtube:<id>`,
   `podcast:<feed>:<guid>`) into `dedupe_key` risks destabilising the
   intake match path (`db/queries.ts:306-311`) and the rename/temporal
   invariants.
2. `canonical_url` cannot serve podcast/social identity (shortcode vs URL
   variants; feed:guid has no URL at all).
3. An associated `item_identity(item_key UNIQUE, source_item_id FK,
   platform, platform_item_id, canonical_url, hashes…)` table gives
   `ONE PLATFORM ITEM = ONE PERSISTENT ITEM IDENTITY` without touching the
   hot intake row, and lets YouTube/Instagram/Facebook/podcast/web/PubMed/
   DOI key formats coexist with the existing URL dedupe.
4. D1 design: `item_key TEXT PRIMARY KEY`-shaped map + `UNIQUE
   (platform, platform_item_id)` guards; `source_items` keeps its current
   columns untouched. D1 sprint drafts the DDL; D0 applies nothing.

## 11. Process-state storage recommendation

Same pattern: associated `item_processing_state` table keyed to item
identity — not new columns on `source_items`. Stores
`processing_state` (`DISCOVERED…COMPLETE` + retryable `FAILED_*`),
`processing_version / classifier_version / evidence_policy_version`,
hashes (`metadata_hash, text_hash, transcript_hash, media_fingerprint`),
`first/last_processed_at`, `failure_state`, `retry_count`, and the last
material reprocess reason (`TRANSCRIPT_CHANGED, CONTENT_CHANGED,
MATERIAL_METADATA_CHANGE, NEW_EVIDENCE, EVIDENCE_POLICY_CHANGED,
CLASSIFIER_VERSION_UPGRADE, PREVIOUS_FAILURE, MANUAL_REVIEW_REQUEST` with
why/when/version/diff). Rationale: keeps Temporal V2 row-shape tests green,
keeps intake writes small, and makes "process once" enforceable at the
ledger layer (`COMPLETE` rows are skipped by normal runs).

## 12. Verdict taxonomy reconciliation

Frozen vocabulary (no competing canonical set found):

`SUPPORTED, PARTIALLY_SUPPORTED, MIXED, INSUFFICIENT_EVIDENCE, CONTRADICTED,
OUTDATED, MISLEADING_CONTEXT`

Existing partial taxonomies mapped, not duplicated:

- Research pool `DISCOVERED/DUPLICATE/INTEGRITY_BLOCKED/INSUFFICIENT_EVIDENCE/
  ELIGIBLE/NOT_EDITORIALLY_RELEVANT/USED` → pool eligibility stays; only the
  `INSUFFICIENT_EVIDENCE` terminal overlaps and is shared verbatim.
- `ResearchEvidenceStatusSchema` (+`INSUFFICIENT_EVIDENCE`),
  `StillValidStatusSchema` (`NOT_REASSESSED/STILL_SUPPORTED/CONTESTED/
  CONTRADICTED`) → `STILL_SUPPORTED≈SUPPORTED`, `CONTESTED≈MIXED`,
  `CONTRADICTED=CONTRADICTED`; the 7-state verdict is the editorial layer,
  pool/research statuses remain eligibility/integrity signals.
- Date verdicts (`FRESH/ACTIVE/UNDATED/STALE`), `REVALIDATION_REQUIRED`,
  relevance `IMPROVED/NO_MEANINGFUL_CHANGE/REGRESSED/INSUFFICIENT_EVIDENCE`
  → orthogonal axes (freshness / revalidation / learning measurement),
  never substitutes for the evidence verdict.
- Hard rule frozen: `ACTOR STATEMENT ≠ SCIENTIFIC EVIDENCE`; discovery
  provenance and evidence provenance stored separately; discovery value and
  evidence value scored separately.
