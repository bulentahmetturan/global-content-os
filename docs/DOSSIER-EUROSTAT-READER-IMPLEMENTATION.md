## Units
FETCH_UNIT = one request (one reference year, geo TR, sex T, age TOTAL, unit RT, about 93 cells, 11 KB). CANONICAL_OBSERVATION_UNIT = one (cause code, reference year) cell = one source item = one observation. Identity (`DATASET_RELEASE_KEY`) = dataset, geo, sex, age, unit, cause code, year, value, status flag; labels are never part of it.

## Findings (measured or discovered; some correct the design)
1. **Per-item D1 cost is about 20.5 statements (ingest max 21, derive max 30), not the design estimate of about 10.** A full 91-item run is about 1,865 statements, not about 920. The 240 budget is nevertheless what the stated rule selects (smallest ladder budget that completes, never hits the statement guard, fits the heaviest unit, takes at most 10 operator invocations, stays under half the 800 ceiling). Max measured 212 statements per invocation (588 below the ceiling); the smallest viable budget is about 57. The runner unit estimates (23 / 45) cover the measured costs. Lease 45 s is derived from recorded production D1 timing, **not measured** (local wall is a proxy and not Worker CPU).
2. **A label change would have created a duplicate observation.** The origin identity is stable, but the generic dedupe key includes the concept id, so a renamed label resolved to a NEW concept and a second observation. Fix: one runner guard, limited to `DATASET_RELEASE_KEY` origins, skips observing an origin that already has an observation (existence, not `created`, so a unit killed between staging and its observation still completes on resume). ClinicalTrials and OECD paths are unaffected (different identity strategies).
3. **Revision (superseded by the gap closure below).** The first implementation kept a revised cell as a second origin but the aggregate went UNKNOWN; closed in the next section.
4. **Overlap is measured, not assumed:** the exact-label overlap with the research-activity concepts in the local state is computed by the tests (currently "Neoplasms" only). Under unknown granularity it stays WATCH: 0 candidates, 0 snapshots, 0 reviews.
5. **Concurrency (superseded by the gap closure below):** closed for the canary execution model by mechanical lease serialization; global multi-writer safety is deferred.
6. Missing cells are UNKNOWN: written only as UNKNOWN tombstones for their release (see below) and never zero; a source-reported zero stays a measured zero. All-cause aggregates are context; Eurostat `_OTH` residual categories are `REVIEW_REQUIRED`.

## Gap closure (2026-10-05, before a separately authorized bounded canary)

**A. Current value of a revised cell (P2 hard gate, closed).** Identity is now cell + release + value + flag (`...|time=2023|rel=<dataset updated, UTC>|v=..|f=..`); the same release and content is the same origin (replay = no-op), any other release or value is a new origin (history immutable). The aggregate (aggregation.ts `selectEffectiveRelease`, applied only to `STATISTICAL_RELEASE_SOURCES`, so no other source pays or changes anything) chooses the current row.
`EUROSTAT_CURRENT_VALUE_PRECEDENCE`: per canonical cell (dataset, geo, sex, age, unit, icd10, reference year) the origin with the greatest VALID release instant is current; equal greatest instants with different (value, flag) are ambiguous and stay effective together (aggregate UNKNOWN, fail closed); an unparsable `rel` never wins and with no valid `rel` all rows stay effective; a current origin whose value is UNKNOWN (the newest release carries no value, written as a tombstone; Eurostat exposes no explicit withdrawal) removes the cell from support and its old derived aggregate is removed (never zero, never the stale value). Insertion time and row ids are never used. Reader ordering signal: only the dataset `updated` instant exists in the Eurostat contract; no release number is invented, and the reference year is part of the cell, not of the ordering. `explainEurostatCell` reports winner, reason and the whole history. Matrix tested end to end: first, replay, same-release conflict, newer same value, newer changed value, late older release, sequential revisions, revision after a kill and resume, missing to present, present to missing, ambiguous and invalid ordering, invalid release metadata at ingest.
Known edge: candidate snapshots cite representative provenance from observations; a superseded observation could be cited there. No candidate exists in the canary (0 expected); not changed here.

**B. Concept-writer concurrency (canary scope, closed; global deferred).** `dossier_concepts` has no uniqueness constraint on the normalized label and no schema change is approved, so the V2 runner serializes concept proposers: a V2 lease is granted by ONE statement only if no other canary run (any reader or profile) holds an unexpired lease (`CONCEPT_PROPOSER_BUSY`), and a V2 invocation stops starting units when less than a margin of its lease remains (so a slow invocation cannot still be writing when another takes over). V1 keeps its original statement. Profile V2 now carries `concurrency = {max_concurrent_v2_runs: 1, max_concurrent_concept_proposers: 1}` and `oecd = OFF`, validated. `CANARY_CONCEPT_WRITER_CONCURRENCY = PASS`; `GLOBAL_CONCEPT_WRITER_CONCURRENCY = DEFERRED_REQUIRES_SCHEMA_OR_LATER_HARDENING`. Not reproducible locally: true parallel database contention (the SQLite harness has one connection and rejects nested transactions); the tests prove the lease statement refuses, expiry allows takeover, the deadline stops units, and no duplicate normalized labels ever appear in the resulting states.

**C. Lineage.** `LINEAGE_DOUBLE_COUNT_PROTECTION = PASS_FOR_CANARY`: tested with all three sources in one state (research activity + Eurostat = 2 families; Eurostat + OECD = 1; all three = 2, never 3). `EXPLICIT_SOURCE_LINEAGE_HOOK = DEFERRED_NON_BLOCKING` (product maturity, not built).

**D. Production CPU and lease.** `PRODUCTION_CPU_MEASURED = NO`, `PRODUCTION_LEASE_MEASURED = NO`; initial lease 45 s is a conservative contract, not a proven optimum. They are measured during the canary (`docs/generated/dossier-eurostat-canary-hard-limits-v1.json`, prepared not executed, with hard-stop criteria and a capture list) and keep blocking `PRODUCTION_ACTIVATION_READY`.

**Runner guard audit.** Explicit regressions: label-driven duplicates are prevented; a unit killed between staging and its observation is completed on resume (the guard checks for an observation, not for `created`); ClinicalTrials (a re-seen study that gains a condition still gains an observation) and OECD (identity strategy is not DATASET_RELEASE_KEY) are unaffected; a valid revision is never suppressed (different origin); an incomplete observation never becomes success.

**Re-measured after the changes:** 240 statements per invocation, max 212 (588 below the 800 ceiling), about 21.4 statements per item, 10 operator invocations for one 91-item run, one source request; heaviest unit 31 statements (runner estimates 23 / 45 hold). Lease and CPU unmeasured in production.
